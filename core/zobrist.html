AHC CORE / ZOBRIST

状態を64bitに畳む

ahc::ZobristTable は特徴ごとのランダムな64bit値を持ち、XORで状態をすばやく比較します。

core入口仕組みAPI境界

特徴をXORする

#include "core/zobrist.hpp"

ahc::ZobristTable z(100, 1234); // 100個のtoken
std::uint64_t hash = 0;
z.apply(hash, 7);               // 特徴7を追加
z.apply(hash, 7);               // 特徴7を削除。hashは0に戻る
hash = z.update(hash, 12);      // 別の特徴を追加

API

表と更新
呼び出し意味
ZobristTable(count, seed)seedからcount個を決定的に作る。count=0も可。
z[i]高速な未検査アクセス。i < size() が前提。
z.at(i) / z.token(i)検査付き。範囲外は std::out_of_range。
z.update(hash, i)hash ^ z.token(i) を返す。
z.apply(hash, i)hashをその場で更新する。
zobrist_update(hash, token)表なしで1つのtokenをXORする。

同じseedなら同じ表です。ZobristTable(count, rng) と書けば、呼び出し元の ahc::Rng を順に消費できます。

境界と失敗例

表の外：速度が必要な内側ループは operator[]、入力に近い場所は at() を選びます。

失敗：特徴の順番を変えれば別のハッシュになると思う。XORは順番を区別しません。位置を特徴の一部にして、位置A・駒Xと位置B・駒Xに別tokenを割り当てます。

失敗：「衝突しない」と考える。64bitハッシュにも衝突はあります。最終判定では元の状態も確認し、ハッシュは候補の絞り込みに使います。

// i == z.size() は範囲外
auto bad = z[i];       // operator[]：未定義動作の可能性
auto checked = z.at(i); // out_of_rangeで発見できる

Rngとの関係

seed constructorは内部で ahc::Rng rng(seed) を1つ作り、rng() の64bit値を順に格納します。つまり、同じseedのRng列と表が対応し、隠れた乱数源はありません。

実行可能な確認は tests/zobrist_test.cpp にあります。
