03 / EULER TOURの辺配列

木を「辺の列」として持つ

親・子・兄弟のリンクを持つNodeを作らず、深さ優先で歩くときの前進と後退を配列に保存します。メモリを軽くしたいときの版です。

Euler Tourは「歩き方」の記録

深さ優先で木を歩くと、枝を進む回数と戻る回数が決まります。その順番を curr_tour_ に並べ、同じ State を前後させます。

向いている用途：ObjectPoolや4本のリンクを持つNodeを避けたいとき。配列を連続して扱い、メモリ使用量を抑えたいとき。

配列で木を更新する

leaves_ と buckets_

leaves_ は現在の葉のEvaluator/Hashです。新しい候補は candidate.parent の番号ごとに buckets_ へ分け、次のTourを組み立てます。ここでのparentはNode IDではなく、現在の葉の番号です。

direct_road_ と path

分岐のない一本道は direct_road_ に移し、毎回同じ区間を歩く量を減らします。解を返すときはforwardでActionを足し、backwardで最後のActionを引きます。

Euler Tour版で必要なもの
場所あなたが決めること守ること
Hash状態を表すハッシュの型と更新。同じ状態を同じ値にする。衝突時の扱いも考える。
Action操作の内容。operator== も実装。Tour更新がAction同士を比較する。既定コンストラクタも初期化する。
Evaluator状態の評価情報と evaluate()。小さいほど良い。葉配列に多数コピーされるので小さく。
State::make_initial_node初期Stateの {Evaluator, Hash} を返す。この版はroot Nodeを引数に取らない。初期値はここで作る。
State::expandActionを列挙し、forward後の値を selector.push(Candidate, finished) へ渡す。Candidate.parent は現在の葉番号。Selectorへ渡すCandidateの順序と意味を崩さない。
move_forward/backwardActionの差分を適用・取り消す。Tourの -1 と -2 が対になり、同じStateに戻る。

記号の注意：-1は前進、-2は後退です。Actionの値が-1や-2という意味ではありません。これは curr_tour_ の第一要素（leaf_index）専用の印です。

最小利用手順

Stateを作る→make_initial_node→Tourを再構築→Action列
#include "beam-search/euler-tour-edges.hpp"

using namespace beam_search;

Config config{/* max_turn */ 100, /* beam_width */ 200,
              /* tour_capacity */ 100000, /* hash_map_capacity */ 4096};
State state{/* input */};
vector<Action> answer = beam_search(config, state);

この版の初期Evaluator/Hashは State::make_initial_node() が返します。tour_capacity は前進辺・後退辺・葉のタプルを含むTour全体の予約容量です。

典型的な失敗

parentをNode IDと思う

buckets_[candidate.parent] の番号は、現在の leaves_ における葉番号です。Candidateを作るときに、別の配列の番号を渡さないでください。

forwardとbackwardが対でない

Tourを一周したあとStateが初期状態に戻るか確認します。配列・評価・hashを比較すると差分漏れを見つけやすくなります。

Actionの等値比較がない

Action::operator== は一本道の圧縮で使います。比較が常にfalseだと、Tourが必要以上に長くなることがあります。

容量・ライブラリ不足

tour_capacity と hash_map_capacity を小さくしすぎないでください。Selectorは atcoder::segtree を使うため、AtCoder Libraryが見えるコンパイル環境も必要です。
