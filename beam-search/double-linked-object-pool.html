01 / 二重連鎖木 + OBJECTPOOL

まず使うなら、この通常版

探索木の各ノードをリンクでつなぎ、不要になったノードの場所を再利用します。Actionが毎回1ターン進む問題の基本形です。

木を歩き、状態だけを差分更新する

木の枝を1本進むときは move_forward、戻るときは move_backward。同じ State を往復させるので、状態の作り直しを減らせます。

向いている用途：1回のActionが1ターン、メモリに余裕があり、木の親子関係をデバッグしやすく見たいとき。

部品の役割

Tree：探索木を保つ

候補を葉として追加し、次のターンで葉を展開します。不要な葉は親をたどって削除します。深さ優先で歩くため、State の往復が使えます。

Selector：上位だけを残す

候補をハッシュで重複排除し、評価値の小さいものを beam_width 個まで保持します。満杯のときは最も悪い候補をセグメント木で追い出します。

最小利用手順

Stateを初期化→rootを作る→beam_search→Action列

Hash initial_hash = /* initial stateのhash */;
Node root(Action{}, initial_evaluator, initial_hash);

固定ターン型では finished=false のまま最後まで進め、戻ったAction列を使います。ターン最小化型では、完成した候補だけ finished=true にします。

典型的な失敗

戻ったStateが少し違う

forward だけで確認すると見つけにくいバグです。Actionをランダムに選び、forward→backward後に、配列・評価・hashがすべて元に戻るテストを作ります。

幅や容量を0にする

beam_width、nodes_capacity、hash_map_capacity は正の値にします。HashMapの容量は候補数より十分大きく（目安4〜16倍）します。

同じHashを無条件に同一視する

hash衝突はあり得ます。必要なら状態の一部を確認するか、衝突確率を十分下げます。衝突を見落とすと、正しい枝が消えます。

rootの意味を取り違える

rootは「初期状態の評価とhashを持つノード」です。初期Stateを1手進めた値をrootに入れないでください。
