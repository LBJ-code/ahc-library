02 / 1 ACTIONで複数ターン

時間を飛び越えるAction

移動の予約、複数年のシミュレーション、完了まで数ターンかかる操作。1つのActionが2ターン以上先へ進む問題には、この版を使います。

stepごとに候補を待たせる

通常版は次のターンの候補を1列に置きます。この版は、step=1、step=2、…を別々の Selector に入れ、時間が来た列から取り出します。

向いている用途：Actionごとに進むターン数が違う問題。1ターンにそろえるためのダミーActionを大量に作りたくないとき。

何が通常版と違うか

MultiSelectors

push(..., step) が step 番目のSelectorへ候補を送ります。ビーム幅とHashMapは各Selectorごとに独立しています。毎ターン、先頭のSelectorを pop_selector() で使います。

遅延削除

先へ飛ぶActionの子がまだ後のSelectorに残っています。葉をすぐ消すと親への道が失われます。remove_check_turn で、子が追加される可能性がなくなってから削除します。

stepの注意：step=3 は「候補を3回Selectorへ入れる」という意味ではありません。現在のStateから、3ターン後の結果へ進むActionであることを、State・Evaluator・Hashの3つでそろえてください。

最小利用手順

Stateとroot→expandでstepを付ける→Selector列から順に処理→Action列
#include "beam-search/multi-turn.hpp"

using namespace beam_search;

Config config{/* max_turn */ 200, /* beam_width */ 300,
              /* nodes_capacity */ 80000, /* hash_map_capacity */ 8192};
State state{/* input */};
Evaluator initial_evaluator{/* initial state */};
Hash initial_hash = /* initial stateのhash */;
Node root(Action{}, initial_evaluator, initial_hash);
vector<Action> answer = beam_search(config, state, root);

State::expand の中で、通常の一手なら step=1、2ターン先へ進むなら step=2 のように渡します。最終ターンにはSelectorの最良候補を返すため、候補が空にならない設計が必要です。

典型的な失敗

stepと状態の時間がずれる

step=3 と言いながら1ターン後のEvaluatorを渡すと、未来の候補を間違った評価で比べます。Action適用後の「完了時点」を一つのテストで確認します。

飛ぶ枝を早く削除する

stepが大きい枝は、今ターンのselectorに現れなくても後で子を生みます。remove_check_turn の考え方を壊さないようにします。

step=0や過大なstep

step=0 は列の意味を壊します。残りの探索ターンを超えるstepを許すなら、その扱いを問題側で決めます。

候補ゼロのまま最終ターン

最終ターンの calc_best_candidate() は候補がある前提です。Actionを全て弾く条件、容量不足、finished判定を切り分けます。
